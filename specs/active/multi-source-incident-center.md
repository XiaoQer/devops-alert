# 多源生产事故中心

## 状态

已确认，实施中。

## 背景与目标

从零建设独立生产事故智能平台。平台不把 Prometheus 告警直接等同于事故，而是接收多源事件，形成 SignalEvent、Alert 和 Incident 独立模型；AlertGroup 作为 Alert 之上的持久化运营投影压缩高可信相似告警，再通过可解释关联、自动取证和受约束 AI 分析形成事故闭环。

## 范围

- 一个统一 UI 和一个逻辑核心控制器；
- SignalEvent、Alert、Incident、DiagnosisRun 四个独立领域对象；
- AlertGroup 和 AlertGroupMember 持久化运营投影；
- 告警、事故运营和诊断任务三套状态机；
- Alertmanager、CloudEvents 和人工报告三个首批入口；
- 轻量服务目录、所有者和一跳依赖；
- 规则优先、可解释的事故关联；
- 通用基础诊断和五类首批症状增强包；
- 预定义只读查询、证据标准化、不可变快照和 AI 可信报告；
- 认领、指派、合并拆分、缓解、恢复观察、解决和关闭；
- 与故障注入平台物理隔离的公开联调契约。

## 非目标

- 复制旧项目源码、数据库、迁移或 Git 历史；
- 故障注入、实验恢复、Chaos 权限和评测标准答案；
- 首版机器学习自动关联；
- AI 自主查询和自动修复；
- 首版 Kafka、图数据库、完整 Backstage 和全量外部连接器。

## 设计

完整设计见 `docs/superpowers/specs/2026-08-24-multi-source-incident-center-design.md`。

### 技术基线

- 核心控制器和可选 Worker 使用 Python；
- HTTP API 使用 FastAPI，契约模型使用 Pydantic；
- 数据访问使用 SQLAlchemy，迁移使用 Alembic，主数据库使用 MySQL 8.4；
- 前端使用 Vue 3、TypeScript、Vite 和 Pinia；
- 前端接口类型从后端 OpenAPI 契约生成；
- 首期异步任务由 MySQL 持久任务、租约和超时接管承载，不引入 Kafka；
- 测试使用 Pytest、Vitest 和 Playwright；
- 前后端独立构建，默认成套部署，可选 Worker 独立部署。

实施必须拆分为独立阶段：

1. 工程基线、独立领域模型、DiagnosisRun 和兼容入口；
2. 服务目录与规则关联；
3. 通用诊断与首批增强包；
4. 事故运营与恢复闭环；
5. 非生产盲测与扩展适配器；
6. 积累人工反馈后再评估学习型关联候选。

## 安全与恢复

- 外部输入独立认证、限流、Schema、大小和字段限制；
- Secret、无界原始负载和实验身份不进入事故或 AI；
- 关联失败时保留事件并创建独立事故，不扩大误合并；
- 数据源或 AI 失败不阻断人工事故处置；
- 历史事件、快照和报告不可变，新结果形成新版本；
- 生产部署不得声明故障注入或实验资源写权限。

## 验收条件

- 三个首批入口输出同一内部契约并通过幂等、乱序、恢复、脱敏和容量测试；
- SignalEvent、Alert、Incident、DiagnosisRun 可独立查询和审计；
- 相似 Alert 可确定性归入可解释 AlertGroup，原始事实和成员关系保持可追溯；
- 无关、跨环境和低可信告警不自动误合并；
- 每次自动关联能够解释使用的规则和事实；
- 无专用增强包时仍形成通用基础快照并标记覆盖限制；
- AI 只能引用真实证据，冲突报告进入人工复核；
- 告警恢复不会自动关闭事故，诊断失败不会改变事故运营状态；
- 项目制品、数据库、权限和部署不依赖故障注入平台。

## 验证证据

- 后端任务 1–6 已完成：工程基线、四个领域模型、三套状态策略、MySQL 8.4 初始迁移、原子且幂等的人工报告业务服务、认证且有界的人工报告 API，以及四类领域资源独立读取 API；
- 人工报告服务已验证正常创建、相同内容重放、不同内容冲突、并发唯一、失败全量回滚、实验身份拒绝和有界审计；
- 人工报告 API 已验证认证、幂等键、字段、标签、未来时间、声明及分块请求体容量、数据库故障和安全错误响应；
- 四类读取 API 已验证独立字段契约、认证、统一未找到响应和单表单查询边界；
- 历史 PostgreSQL Compose 独立环境中曾有 91 项测试通过、覆盖率 95.21%；当前 MySQL 8.4 全部后端测试为 133 项通过，最终覆盖率验收见 MySQL 基线验证记录；
- 真实 HTTP 冒烟验证首次创建 201、相同内容重放 200、四个 ID 一致，以及四类资源读取 4/4 成功；
- 密钥形态扫描无命中；禁止实验身份仅出现在拒绝代码、边界测试和说明文档中；
- Ruff、格式检查、Mypy、依赖一致性、迁移升级/降级和 ORM 元数据一致性检查通过；
- Alertmanager 与 CloudEvents 两类外部适配器、共享接入服务和 Alert 投影已通过 206 项 MySQL 后端测试及真实 HTTP 冒烟，覆盖率 96.82%；
- 服务目录与可解释事故关联已按聚焦设计完成，验收证据见 `docs/verification/2026-08-25-service-catalog-correlation.md`；
- 自动取证、DiagnosisRun 自动创建、AI、事故运营写接口和前端尚未实现，不计入当前可用能力。
