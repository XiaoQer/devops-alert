# 可解释告警事件聚类与降噪

## 状态

已确认，待实施。

## 背景与目标

当前平台已经能够接收 Alertmanager、CloudEvents 和人工来源的信号，并使用版本化问题签名把同来源、同问题类型、同症状和同影响范围的 Alert 压缩为 AlertGroup。该能力可以处理完全重复或高度同质的告警风暴，但还不能把同一次故障传播产生的不同告警收敛为一个可理解的事件。

本规格只建设降噪阶段的第一步：在一段时间内，依据时间、实体、服务拓扑、调用关系、问题语义和文本相似度，把相关 Alert 归集为一个告警事件。它不判断事件中的核心告警，不执行根因分析、自动取证或治愈。

完成后，操作员面对几百条告警时，应首先看到少量可解释的告警事件，并能检查每条告警为什么被合并、等待确认或保持独立。

## 范围

- 告警源必须配置可信环境，告警继承来源环境；
- 宽容接收缺少 service 等非协议必需字段的合法告警；
- 标准化来源、环境、状态、严重程度、问题语义、服务范围和资源实体；
- AlertGroup 从“相同问题签名压缩组”演进为“一次告警事件”的运营投影；
- 使用候选召回、可解释多维评分和事件级兼容校验完成聚类；
- 使用确定性文本相似度，并为可选语义相似度提供安全退化接口；
- 支持聚合中、活跃、恢复观察和已关闭的事件生命周期；
- 支持迟到、乱序、恢复、复发、容量滚动和服务重启恢复；
- 支持中置信度待确认、人工确认成员、拆出成员和合并事件；
- 重构告警中心的信息架构、指标口径、事件详情和聚类解释；
- 保留原始 SignalEvent、Alert、历史分组决策和事故关系的完整可追溯性。

## 非目标

- 判断某个告警是否是事件的核心告警；
- 根因排序、因果链分析、自动取证、证据快照或 AI 报告；
- 自动治愈、任意命令执行或监控查询；
- 使用未验证的机器学习分类器直接决定生产聚类；
- 读取 Kubernetes、Prometheus、日志平台或其他外部系统补齐告警字段；
- 仅凭文本相似度完成跨服务自动合并；
- 用告警事件替代 Incident 的认领、调查、缓解和关闭职责；
- 在本阶段引入 Kafka、图数据库或外部向量数据库。

## 设计

### 1. 领域边界

领域链路保持四层独立：

1. `SignalEvent` 是外部系统送达的一次不可变事实；
2. `Alert` 是同一来源条件的触发、更新、恢复和重开的生命周期投影；
3. `AlertGroup` 是一次实际发生的告警事件，可以包含不同来源、不同告警名称和不同症状的相关 Alert；
4. `Incident` 是达到运营门槛后创建的人工处置对象。

产品界面将 AlertGroup 称为“告警事件”。代码和版本化 API 在本阶段保留 AlertGroup 命名，避免无价值的破坏性重命名。

`problem_key` 表示可重复发生的同类问题，AlertGroup 表示一次发生批次。相同 `problem_key` 可以对应多个已经关闭或仍然活跃的 AlertGroup，界面据此展示复发次数，但不得把跨批次历史合并成无限增长的事件。

现有 SignalEvent、Alert、Alert-Incident 关系、AlertGroup 成员和不可变决策必须保留。迁移不得删除或覆盖历史事实。已关闭历史组不自动重新聚类；仍在活动的旧规则组通过有界、可重放任务逐步转换。

### 2. 告警源环境

创建告警源时必须选择稳定环境代码和显示名称。平台内置生产、预生产、测试和开发选项，并允许创建有界的自定义环境。

- 来源配置是环境的唯一可信事实；
- 该来源收到的所有告警继承配置环境；
- 发送内容不必提供环境；
- 发送内容中的环境不能覆盖来源配置；
- 发送内容与来源环境冲突时，接收继续进行并生成有界标准化警告；
- 环境不同是自动聚类的硬排斥条件；
- 平台不访问外部系统猜测或补齐环境。

新增来源没有环境时不能启用。迁移前已经存在且环境未知的来源继续接收，但标记为“环境待配置”；其告警只能在本来源内安全归集，不参与跨来源聚类，直到管理员完成环境配置。历史事实不因来源环境修改而被改写。

### 3. 宽容接入与标准化

适配器只校验协议安全、认证、幂等、容量、类型和协议必需字段，不得因为缺少 service、namespace、pod 或其他业务标签拒绝整批合法告警。

标准化契约包含：

- 来源、可信环境、状态和严重程度；
- 标题、安全摘要、问题类型和标准化症状；
- 服务、工作负载、命名空间、集群和作业；
- 实例、Pod、Node、Container、数据库等资源实体；
- 实际发生时间、恢复时间和平台接收时间。

影响范围按 SERVICE、WORKLOAD、NAMESPACE、CLUSTER、JOB、SOURCE 的固定顺序安全退化。信息不足时仍可形成来源范围事件，但不得虚构服务、拓扑或事故。

未知字段不导致拒绝。平台只保存已识别的有界事实以及未映射字段名摘要，不保存未知字段值、无界原始负载或高风险内容。后续可以在告警源上配置有界字段映射，把来源字段映射为平台标准字段，无需修改发送端。

详情页必须区分“告警源报告”“平台标准化结果”和“平台聚类判断”。来源文本不能被改写成平台已经确认的事实结论。

### 4. 候选召回

新 Alert 到达时只召回有限候选，不与全部历史事件比较。普通候选必须：

- 环境相同；
- 最近十五分钟内仍有活动；
- 至少存在相同实体、相同服务、拓扑一跳相邻、明确调用关系或相同问题签名之一。

跨来源允许召回。环境不同、事件关闭且超过迟到窗口、明显超出事件时间范围或只有文字相似而没有实体与关系锚点时直接排除。

相同 Alert 的更新和恢复始终回到原事件，不受普通候选窗口限制。超过十五分钟的新 Alert 只有在原事件仍活跃且存在相同实体、相同问题签名或直接调用关系等强锚点时，才可继续成为候选。

召回查询必须有固定上限、稳定排序和覆盖索引。候选过多时安全退化为待确认或独立事件，不能随机选择。

### 5. 聚类评分

第一版采用版本化、可回放的确定性评分，不使用训练分类器决定最终归属。默认总分为一百分：

| 维度 | 最高分 | 含义 |
| --- | ---: | --- |
| 实体与服务 | 35 | 相同资源高于相同服务和相同范围 |
| 拓扑与调用关系 | 25 | 直接调用或依赖高于普通邻接 |
| 时间接近度 | 20 | 时间越接近得分越高 |
| 问题语义 | 15 | 问题类型、症状和文本相似度 |
| 已确认历史规则 | 5 | 人工合并或拆分形成的明确经验 |

默认决策阈值：

- 七十分及以上且满足强锚点：自动加入；
- 五十分至六十九分：待人工确认；
- 五十分以下：保持独立；
- 得分最高的两个候选差距不足十分：不得自动选择，进入待确认；
- 任一硬排斥条件命中时不计算自动合并结果。

每次判断保存规则版本、各维度分数、命中事实、候选摘要、固定原因码和中文解释。合并与不合并都必须可解释。

### 6. 防止链式误合并

系统不得因为 A 与 B 相似、B 与 C 相似就直接把 A、B、C 全部合并。新成员需要同时与事件整体画像兼容。

事件画像是版本化派生数据，至少包含：

- 环境、服务集合、实体集合和影响范围；
- 拓扑覆盖及调用关系；
- 问题类型和症状分布；
- 标准化文本中心；
- 首次发生和最近活动时间；
- 自动确认、人工确认和待确认成员统计。

成员加入后重新生成画像。第一版自动聚类最多覆盖两跳拓扑；超过两跳、事件画像明显分裂或新成员只匹配单个边缘成员时进入待确认。实现不得使用无约束连通分量直接扩张事件。

### 7. 文本相似度

文本相似度只处理标准化后的安全标题、摘要、告警名称和标准化症状，不接收原始 Webhook。

始终可用的确定性层执行大小写、空白和标点规范化，分离时间戳、UUID、请求编号、IP 和资源标识等动态片段，再计算词元和字符片段相似度。相同输入、规则版本和语言配置必须得到相同结果。

系统提供可选的版本化语义相似度能力接口。注册能力可把安全文本转换为向量并返回模型名称、模型版本和相似度；超时、失败或未注册时退化到确定性文本相似度，不阻断接收、去重和聚类。派生向量按安全文本摘要和模型版本缓存，不保存模型隐藏推理。

确定性和语义结果转换为有界的综合文本特征，但问题语义维度总计不得超过十五分。文本相似度不能单独满足强锚点条件。

第一阶段记录人工反馈样本，但不训练或自动上线分类模型。未来分类器必须有独立规格、离线回放、误合并率门槛、灰度和回滚机制。

### 8. 时间窗口与生命周期

默认策略使用事件时间和持久任务：

| 参数 | 默认值 | 用途 |
| --- | ---: | --- |
| 首批观察 | 30 秒 | 接收同一异常的第一波告警 |
| 普通候选回看 | 15 分钟 | 召回近期相关事件 |
| 恢复观察 | 5 分钟 | 确认所有成员恢复后是否稳定 |
| 迟到容忍 | 5 分钟 | 处理传输延迟和队列积压 |
| 事件成员上限 | 1,000 | 防止单事件无界增长 |

事件状态为：

- `FORMING`：首条告警已可见，首批仍在聚合；
- `ACTIVE`：至少有一个成员处于活动状态；
- `OBSERVING`：全部成员已恢复，正在等待稳定；
- `CLOSED`：恢复观察完成，本次发生批次结束。

首条告警立即创建 FORMING 事件，严重告警不因三十秒观察而隐藏。三十秒内全部恢复的事件仍然保留并标记为短暂抖动。

相关新成员加入时更新最近活动时间。所有成员恢复后进入 OBSERVING；五分钟内再次触发则返回 ACTIVE，五分钟无新触发则关闭。事件只要仍有活动成员就不按固定时长强制关闭。

事件关闭后真正的新触发创建新的 AlertGroup，并通过相同 problem_key 表示复发。已经关闭的事件不因新一轮故障重新打开。

平台同时保存发生时间和接收时间。实际属于原事件且在关闭后五分钟内送达的迟到告警可以补入原事件并生成新版本；如果迟到事实证明先前关闭错误，允许执行有审计的状态纠正。超过迟到容忍的输入不得静默改写历史，只能创建新事件或保存可能相关关系。

超过一千个成员时创建后继事件并保存同一风暴关系。所有计时与状态转换由 MySQL 持久任务、租约和过期接管驱动，服务重启不得丢失进度。

参数属于版本化平台策略。首版不自动按模型修改生产参数；积累历史后只生成按服务的推荐值，由管理员确认生效。

### 9. 人工确认与反馈

第一阶段支持：

- 确认待确认成员属于当前事件；
- 从事件拆出一个或多个成员；
- 合并两个兼容的告警事件。

人工操作使用幂等键、当前版本、行锁和单事务。操作必须保存主体、时间、原因、修改前后版本和不可变审计；不得删除原始成员关系或覆盖旧聚类决策。修改后重新生成事件画像、统计和后继关联任务。

跨环境事件不能人工合并。已经进入不同终态事故的事件不能直接合并，必须先通过独立事故运营流程处理冲突。失败、并发旧版本和结果未知分别使用稳定错误语义。

人工确认、拆分和合并形成有界正负反馈样本。反馈只供离线评估和未来独立模型规格使用，本阶段不改变线上规则权重。

### 10. 告警中心信息架构

告警中心回答信号如何降噪并形成告警事件；事故中心回答哪些事件需要人工处置以及处置进展。两者不得使用相同的列表语言和状态含义。

告警中心一级视图为：当前事件、待确认、历史事件和原始告警。默认展示当前事件。

顶部指标必须标明时间口径，并至少区分：当前活跃事件、当前严重事件、当前活动原始告警、二十四小时已恢复事件、二十四小时原始告警、二十四小时降噪率和当前告警风暴。当前与历史数据不得混在同一指标或默认列表中。

事件卡片展示中文标题、状态、最高严重程度、可信环境、服务、友好来源名称、首次发生、持续时间、最近活动、原始信号数、Alert 数、影响资源数、待确认成员数、事故关系和复发次数。内部来源 ID 不作为主界面名称。

事件详情按以下顺序组织：

1. 发生了什么；
2. 是否仍在持续；
3. 影响的服务和资源；
4. 为什么归为同一事件；
5. 告警传播时间线；
6. 待确认成员；
7. 原始告警；
8. 是否进入事故及明确原因。

事故关系必须使用真实状态和判定原因，不得用“待关联事故”代替未知、跳过、未达门槛、处理中、已创建、已并入或存在歧义。

页面默认使用业务语言，技术规则和 ID 收入可展开审计区域。辅助文字必须满足可读对比度，正文与次要文字字号不能依赖过小字体；关键状态不能只靠颜色表达。桌面常用宽度、键盘操作、二倍缩放、空状态、失败重试和长文本均纳入前端验收。

### 11. 事故关联兼容

AlertGroup 完成聚类或人工修改后，才生成或收敛组级事故关联任务。Incident 仍由独立门槛和关联策略决定，告警事件形成不等于事故创建。

已有 Incident 关系不得因事件画像刷新而静默迁移。需要改变已有关联时保存明确候选和人工操作入口。聚类服务不可用时保留 Alert 和持久任务，不得绕过 AlertGroup 直接创建事故。

## 安全与恢复

- 所有输入继续执行独立认证、幂等、容量、类型、时间和敏感字段边界；
- 原始负载、Secret、未知字段值和模型隐藏推理不进入事件画像、决策、日志或 API；
- 聚类、人工反馈和生命周期任务使用持久任务、租约、最大尝试和过期接管；
- 同一 Alert 同一轮次最多拥有一个有效自动成员归属；待确认关系不能被误读为正式成员；
- 聚类任务失败时保留 Alert 并安全退化为待处理，不丢弃、不随机合并；
- 文本能力不可用不阻断主链路；服务目录缺失不阻断接收和来源范围聚类；
- 决策、成员变化和事件版本可重放、可审计，历史事实不可覆盖；
- 批量迁移、重组和回放必须有固定批次上限、幂等检查和失败回滚；
- 任何自动聚类都必须可用相同规则版本和输入事实重新计算。

## 验收条件

- 告警源创建和编辑可以配置可信环境，告警继承来源环境，发送内容不能覆盖；
- 缺少 service 的合法告警正常接收，并按稳定范围安全退化；
- 同一来源事件幂等重放不增加 SignalEvent、Alert 或事件成员；
- 同一故障源在十分钟内产生一百至一千条不同告警时，可收敛为少量主要事件且不丢失原始事实；
- 同环境、同调用链的不同症状在强锚点和高分条件下可以自动聚合；
- 同时发生但环境不同的告警绝不合并；
- 只有文本相似而没有实体、服务、拓扑、调用或问题签名锚点的告警绝不自动合并；
- 得分最高的两个候选差距不足十分时进入待确认，不随机选择；
- 事件整体画像阻止无约束 A-B-C 链式扩张，自动拓扑覆盖不超过两跳；
- 文本语义能力未注册、超时或失败时，确定性聚类继续运行；
- FORMING、ACTIVE、OBSERVING 和 CLOSED 转换通过持久任务执行，服务重启后继续；
- 迟到、乱序、短暂抖动、恢复观察、真正复发和容量滚动均有可重放测试；
- 每次自动加入、待确认、保持独立和硬排除都有固定原因码、分项得分和中文解释；
- 人工确认、拆分和合并使用幂等、版本检查、单事务和不可变审计，不删除原始事实；
- 告警中心明确区分当前、待确认、历史和原始告警，所有概况指标展示真实时间口径；
- 事件详情展示归集了什么、为什么归集、结果如何、影响范围、传播时间线和真实事故判定；
- 内部来源 ID、技术规则和原始来源描述不会被当成主界面名称或平台结论；
- 一千条并发接入、精确重放、任务重试和人工并发操作满足容量、幂等、回滚和有界查询要求；
- 后端测试、迁移往返、Ruff、格式检查、Mypy、前端单元测试、生产构建和关键浏览器旅程全部通过；
- 当前能力文档明确标注本阶段未实现核心告警识别、根因定位和自动治愈。
