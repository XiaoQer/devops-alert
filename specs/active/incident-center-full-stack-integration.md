# 事故中心前后端完整联调

## 状态

已确认范围，等待规格验收。

## 背景与目标

事故中心前端已经完成视觉与交互原型，但仍从组件内静态数组读取演示数据，认领状态也只存在于浏览器内存。当前后端能够创建和关联 Incident，却只提供单资源读取和关联任务接口，不能直接支持事故队列、聚合详情和真实认领。

本阶段建立事故中心第一个真实纵向闭环：浏览器只展示 MySQL 中已经存在的事故、告警、服务目录和关联决策；事故认领通过后端事务持久化并写入审计。数据或 API 不可用时必须明确显示失败，禁止自动回退到演示数据。

## 范围

### 数据库与领域状态

- 新增 `0003_incident_assignment` MySQL 迁移；
- `incidents` 增加可空 `assignee` 和 `claimed_at`；二者必须同时为空或同时非空；
- 认领成功时将认证主体写入 `assignee`、记录 UTC `claimed_at` 并递增 Incident `version`；
- 精确重复认领由同一主体安全重放，不增加版本或审计；
- 已被其他主体认领、已解决或已关闭的事故拒绝认领；
- 不引入事故解除认领、转派、状态流转或完整用户系统。

### 后端读取 API

新增以下人工控制面接口，全部复用现有 Bearer Token 边界：

1. `GET /api/v1/incidents`
   - 支持 `environment`、`state`、`query`、`limit`、`offset`；
   - `limit` 为 1–100，`offset` 最大 10000；搜索字符串最长 100；
   - 默认按活动事故优先、最近发现时间倒序、ID 稳定排序；
   - 返回有界 `items`、`total`、`limit` 和 `offset`；
   - 每项只包含队列所需字段：事故身份、标题、严重度、状态、服务、环境、负责人、服务团队、发现时间、最近活动时间、关联告警数和版本。

2. `GET /api/v1/incidents/{incident_id}/overview`
   - 返回事故基础字段、负责人、服务团队、关联原因、最多 100 条关联告警、时间线和是否截断；
   - 告警只返回规范化标题、状态、严重度、来源、首次/最近出现时间和版本；
   - 关联原因来自该事故最新的不可变 CorrelationDecision，包含固定结果、规则版本、原因码和中文解释；无决策时返回明确的“暂无关联决策”，不生成推测；
   - 时间线只由已持久化的事故创建、告警关联和认领事实派生，不制造“告警仍在持续”等虚构事件；
   - 不返回原始 SignalEvent 摘要、facts、来源 URI、来源事件键、租约、Secret 或实验身份。

### 后端认领 API

新增 `POST /api/v1/incidents/{incident_id}/claim`：

- 不接收浏览器自报用户名，负责人取自通过认证的服务端主体；
- 在单个 MySQL 事务内锁定 Incident、验证状态、写入负责人、递增版本并追加一条有界 `incident.claimed` 审计；
- 审计仅保存固定原因码，不保存 Token、请求正文或前端显示名称；
- 同一主体重复请求返回 200 和当前结果；其他主体冲突返回 409；不存在或非法 ID 使用统一未找到契约；
- 数据库失败返回安全固定错误且不产生部分写入。

### 前端真实 API 接入

- 删除 `App.vue` 中全部事故演示数组，不保留静态事故兜底；
- 新增独立 API 客户端与响应转换层，将后端英文枚举、UTC 时间和规范化字段转换为现有中文视图模型；
- 页面启动、环境变化和搜索变化时读取真实事故列表；搜索使用短延迟防抖并丢弃过期响应；
- 选择事故时读取真实 overview；列表与详情分别展示加载、空、失败和重试状态；
- 认领按钮调用真实 claim API，成功后刷新列表与详情；冲突或失败显示后端安全错误；
- 页面不得在请求失败时显示演示数据，也不得把 Token、原始错误栈或数据库细节显示给用户；
- 顶部时间改为当前浏览器时间，不继续硬编码日期；
- 保持已验收的三栏布局、中文信息架构和技术详情默认收起。

### 本地认证与部署边界

- 浏览器统一请求同源 `/api/v1/*`；
- Vite 开发服务器代理到 `II_FRONTEND_API_URL`，由开发服务器读取 `II_FRONTEND_API_TOKEN` 并注入 Authorization；
- Token 不使用 `VITE_*` 变量，不进入客户端打包结果、源码、测试快照或日志；
- 正式部署由同源控制器或反向代理完成用户会话到后端主体的转换；本阶段不在浏览器保存共享 Bearer Token；
- 后端不为本地联调放宽 CORS、认证或安全错误边界。

## 非目标

- 自动取证、DiagnosisRun 自动创建、AI 分析或可信报告；
- 事故状态流转、解除认领、转派、合并拆分、恢复和关闭闭环；
- 独立告警、服务目录、关联任务或平台状态页面；
- 生产级用户、角色、组织和 SSO；
- WebSocket、SSE、轮询刷新或实时推送；
- 写入演示事故、从故障注入平台读取数据或使用任何实验身份。

## 数据流

1. Alertmanager、CloudEvents 或人工入口写入规范化 SignalEvent/Alert；
2. 关联任务把符合门槛的 Alert 创建或关联到 Incident；
3. 浏览器通过同源代理读取事故列表；
4. 用户选择事故后读取聚合详情，后端从 Incident、Alert Link、Alert、Service Catalog 和 CorrelationDecision 形成有界只读视图；
5. 用户认领时，后端以认证主体执行单事务认领并写审计；
6. 前端重新读取真实列表和详情，展示数据库确认后的状态。

## 安全与失败策略

- 所有新增接口沿用恒定时间 Token 校验和现有安全错误模型；
- 搜索、分页、告警数量、时间线数量和响应字段均有明确边界；
- 列表不得产生逐事故 N+1 查询，聚合详情使用固定数量查询；
- 数据读取失败不改变事故；认领事务失败完整回滚；
- 空数据库展示真实空状态；后端不可用展示不可用状态和重试操作；
- 未配置本地代理 Token 时请求保持未认证并显示安全失败，不读取或生成演示数据；
- 禁止字段扫描覆盖 API 响应、审计和前端构建产物。

## 验收条件

- MySQL 迁移可升级、降级，并与 ORM 元数据一致；
- 事故列表分页、过滤、搜索、稳定排序和容量边界通过真实 MySQL 测试；
- 聚合详情能展示真实关联告警、服务团队、最新关联解释和持久时间线，且查询有界；
- 认领首次成功、同主体重放、其他主体冲突、不可认领状态、并发收敛、回滚和审计均通过测试；
- 三类非人工 Token 不能访问新增控制面接口；
- 前端测试证明初始加载、筛选搜索、事故切换、加载/空/错误/重试、真实认领和过期请求丢弃；
- 前端源代码中不存在原有四条演示事故内容；
- 浏览器在真实后端和真实 MySQL 上完成列表、详情和认领联调，控制台无错误；
- API 不可用时页面明确失败且不出现任何演示事故；
- Ruff、格式、Mypy、全部 Pytest、Vitest、Vite 构建和托管测试通过。
