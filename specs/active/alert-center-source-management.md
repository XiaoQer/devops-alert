# 告警中心与告警源管理

## 状态

已确认，待实施。

## 背景与目标

平台已经能够接收 Alertmanager、CloudEvents 和人工报告，维护 Alert 并执行可解释事故关联，但操作员无法独立查看告警，外部接入也仍使用全局 Token 和固定地址。

本规格增加独立告警源身份、独立凭据、真实接收状态、告警读取聚合和前端页面，使操作员能够看清告警的来源、检测结果、归并过程和事故关联结果。

完整设计见 `docs/superpowers/specs/2026-08-26-alert-center-source-management-design.md`。

## 范围

- Alertmanager 与 CloudEvents 的用户管理告警源；
- 人工报告、Alertmanager 和 CloudEvents 的系统兼容来源；
- 每个用户来源独立 Webhook、Token、停用和凭据轮换；
- 真实请求验证和有界安全 Receipt；
- Alert 与 SignalEvent 的不可变来源身份；
- 告警列表、统计和聚合详情 API；
- 真实数据驱动的告警中心和告警源管理页面；
- 兼容现有固定接入地址和环境 Token。

## 非目标

- 新增外部适配器；
- 告警确认、关闭、抑制、静默和通知升级；
- 控制器主动探测监控系统；
- AI、自动取证和诊断 Worker；
- RBAC、SSO 和外部密钥管理服务；
- 故障场景、实验身份或实验专用告警。

## 设计

- 来源注册表在现有纯适配器之前完成来源识别、凭据认证和启用状态判断；
- Token 至少包含 256 位随机秘密，数据库只保存不可逆摘要，明文只展示一次；
- 启用来源至少有一个有效凭据，轮换不自动撤销旧凭据；
- SignalEvent、Alert、接入结果和幂等身份加入可信 `alert_source_id`；
- 已有数据回填到确定性系统来源，现有固定入口继续绑定兼容来源；
- 普通接入在单个 MySQL 事务内写入 Receipt、信号、告警、接入结果、审计和必要关联任务；
- 验证入口执行真实认证和 Schema 校验，但不创建领域对象；
- 每个来源最多保留最近 1,000 条且最长 30 天 Receipt；
- 告警中心只读展示告警事实、归并过程和事故关联，不复制事故状态机；
- 告警源状态只依据真实接收事实派生，不宣称未经验证的连接健康。

## 安全与恢复

- Secret 不进入源码、迁移、日志、审计、API 后续读取、测试数据或前端构建；
- 一次性 Token 响应丢失时只能轮换，不提供找回；
- 未认证请求不逐条写数据库，已认证失败只写固定安全原因；
- 类型不匹配、来源停用、凭据撤销和请求超限均在领域写入前拒绝；
- 适配器或事务失败时不产生部分 SignalEvent、Alert 或关联任务；
- 关联失败不阻断告警读取和人工事故处置；
- 禁止实验身份继续在接入、持久化、API 和前端边界生效。

## 验收条件

- 每个用户来源具有独立地址和独立 Token，跨来源凭据不可使用；
- 两个来源发送相同外部事件身份不会冲突或归并；
- 创建与轮换只展示一次 Token，重放不泄漏历史秘密；
- 撤销凭据立即失效，启用来源不能撤销最后一个有效凭据；
- 停用来源拒绝新数据并保留历史告警和 Receipt；
- 验证入口不创建 SignalEvent、Alert、关联任务或 Incident；
- 普通入口支持首次、更新、恢复、精确重放和整批回滚；
- 告警列表能够按状态、严重程度、来源、服务、环境、时间、关键字和事故关联筛选；
- 告警详情展示实际检测结果、来源、归并信号、关联结果和中文解释；
- 前端明确区分加载、空、失败、部分数据、等待首次数据、最近失败和停用；
- API 不可用时不显示演示数据或虚假成功；
- 现有固定入口、事故中心和事故处置回归测试保持通过；
- 自动化验证、静态检查、构建、真实 MySQL 和浏览器验收全部通过。
