# 可解释告警事件聚类与人工纠错验收记录

## 验收范围

本次验收覆盖可信来源环境、宽容接入、候选召回、多维评分、事件画像、生命周期、容量滚动、待确认、人工确认/拆分/合并、告警中心读取契约和真实页面。验收使用本地 MySQL、真实 FastAPI 服务和 Vue 开发服务器，不使用演示数据，也不接入故障注入平台。

## 自动化验证

- 后端统一脚本：Ruff、180 个 Python 文件格式检查、105 个源码文件 Mypy、迁移往返和 558 项测试全部通过；总覆盖率 90.81%。
- 前端：18 个测试文件、76 项 Vitest 全部通过；Vite 生产构建成功。
- Sites Worker：4 项测试通过，覆盖静态资源、应用路由回退、API 不回退应用壳和打包文件完整性。
- 容量与恢复：1,000 条并发接入、1,001 条容量滚动、精确重放、任务租约接管、生命周期恢复和人工并发冲突均包含在统一回归中。

## 并发死锁复现与修复

三路同时执行相同的千条容量测试时，修复前两路稳定出现 MySQL 1213 死锁。堆栈确认冲突发生在 `SignalIntakeService.submit_batch` 写入 Alert 的事务，而不是事件聚类阶段。

接入服务现对 MySQL 1205/1213 使用最多三次全新事务重试，继续沿用唯一约束冲突的幂等收敛；其他数据库错误仍直接传播。修复后相同三路并发测试 3/3 通过，最终整库回归也通过。

## 真实浏览器验收

验收地址为 `http://127.0.0.1:5173/`，后端为 `http://127.0.0.1:8000/`。开发代理与后端使用同一组进程内临时凭据，凭据未输出或写入文档。

- 当前事件、待确认、历史事件和原始告警四个视图均能切换，选中状态明确；
- 概况读取真实 MySQL 事实，当前无活动事件时显示 0，历史与原始告警仍可独立访问；
- 数据库由旧版本升级到 `0010_alert_event_clustering` 后，历史事件统一显示“已关闭”，不再显示“未知状态”；
- 没有新版事件画像记录的旧事件可以打开详情，展示发生了什么、事故判定、归集解释、来源、资源和原始告警；
- 待确认成员接口在旧事件上返回真实 0 条和明确空状态，不再显示“暂时不可用”；
- 浏览器控制台错误和警告为零。

浏览器验收没有制造待确认告警，也没有执行会修改真实数据的确认、拆分或合并；这些写操作的成功、幂等重放、冲突、回滚和前端刷新由自动化测试覆盖。

## 结论与能力边界

本阶段已经完成降噪第一步：在有界时间内把相关 Alert 收敛为少量可解释告警事件，并允许人工纠错。平台仍未实现事件内核心告警识别、根因定位、自动取证、AI 分析或自动治愈；这些能力不得从当前聚类结果中推断为已经完成。
