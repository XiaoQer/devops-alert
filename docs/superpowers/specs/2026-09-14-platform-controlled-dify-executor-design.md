# 平台主控、Dify 受控执行的 Incident 分析设计

## 目标

将 Incident 智能分析设计为一个由平台主程序控制的受限执行流程：平台负责事实、权限、状态、审计与报告发布；Dify 只负责在已授权的有限工具间编排推理，并返回结构化诊断草案。

本设计不把 Dify 视为平台控制面、事实来源或长期存储。

## 核心决策

1. 平台是唯一控制面和唯一事实源。
2. Dify 是无状态的 Workflow 执行器，只能使用平台签发的单次、短有效期能力凭证。
3. Dify 按需调用平台工具，不接收原始告警、完整日志或全部知识库内容。
4. 平台而非 Dify 决定输入范围、工具权限、重试、状态迁移、报告可信度和人工处置。
5. AI 输出默认是草案；只有平台验证通过才是可信报告。

## 责任边界

| 领域 | 平台主程序 | Dify Workflow |
| --- | --- | --- |
| Incident、Alert、Evidence | 读取、冻结、持久化和审计的唯一事实源 | 不保存、不修改 |
| 监控系统 | 通过版本化只读取证包访问 | 无直接凭据、无直接网络访问 |
| 知识库 | 文档审批、版本、范围过滤和检索 | 仅读取平台返回的片段 |
| 诊断任务 | 创建、排队、租约、重试、结束和审计 | 无任务状态 |
| 权限 | 用户鉴权、能力凭证、范围验证 | 仅提交短期凭证 |
| 报告 | 校验、持久化和发布 | 产出结构化草案 |
| 外部副作用 | 人工处置、通知、未来自动化均由平台决定 | 不允许 |

禁止向 Dify 提供 MySQL、Prometheus、Elasticsearch、SkyWalking、飞书、Kubernetes、故障注入平台或其任何凭据。

## 运行流程

```text
操作员：开始分析某个 Incident
          ↓
平台：校验权限、Incident、EvidenceRun 和运行容量
          ↓
平台：创建 DiagnosisRun，冻结输入范围，写入诊断任务
          ↓
平台 Worker：领取任务，签发单次能力凭证，调用固定 Dify Workflow
          ↓
Dify：按需调用平台三项只读工具，输出结构化草案
          ↓
平台：校验输出、引用和事实边界，保存审计与报告
          ↓
前端：只读取平台的运行状态和已验证报告
```

### 启动前校验

平台只有在以下条件都满足时才创建运行：

- 当前用户有 Incident 分析权限；
- Incident 存在；
- 用户选择的 EvidenceRun 属于该 Incident，且状态为 `SUCCEEDED` 或 `PARTIAL`；
- 同一 Incident 没有其他 `QUEUED` 或 `RUNNING` 的 DiagnosisRun；
- Dify 配置、固定 Workflow 和平台工具服务通过健康检查。

创建时在一个事务中冻结：Incident 范围、最多 500 条关联 Alert 的安全投影、所选 EvidenceRun、最多 100 条 EvidenceItem 内容指纹，以及检索知识时允许使用的环境、服务与 Alertname 范围。

## Dify 输入与只读工具

Dify 启动输入保持最小化：

```json
{
  "diagnosis_run_id": "drun_...",
  "goal": "基于固定证据解释当前现象，区分事实与待验证假设",
  "output_contract_version": "v1",
  "capability_token": "短期一次性凭证"
}
```

能力凭证绑定 `diagnosis_run_id`、受众、过期时间和随机 nonce；不写入数据库正文、日志、API 响应或 Dify 输出。

| 平台工具 | Dify 可提交的内容 | 平台强制边界 | 返回上限 |
| --- | --- | --- | --- |
| `get_diagnosis_snapshot` | 无 | 只能读取凭证绑定的运行快照 | 40 KB |
| `get_evidence_detail` | 快照内 EvidenceItem ID | ID 必须在该运行固定快照中 | 单项 8 KB |
| `search_incident_knowledge` | 自然语言问题 | 环境、服务、Alertname 只从快照推导，忽略外来范围 | 最多 5 段、20 KB |

平台为每次工具调用保存受限审计回执：运行号、工具名、请求指纹、结果内容指纹、截断标记、稳定错误码和时间。不会保存能力凭证、原始请求头或 Secret。

## 诊断状态和重试

```text
QUEUED → RUNNING → REPORT_READY
                 ├→ REVIEW_REQUIRED
                 └→ FAILED
```

- `QUEUED`：输入已经冻结，等待平台 Worker。
- `RUNNING`：Worker 持有租约并在调用 Dify。
- `REPORT_READY`：报告通过结构、范围、引用和事实校验。
- `REVIEW_REQUIRED`：Dify 返回了草案，但证据不足、引用错误或事实表达超出证据边界。
- `FAILED`：配置、认证、超时、限流、连接或协议错误导致无法生成草案。

仅对 `dify_timeout`、`dify_rate_limited` 和 `dify_unavailable` 重试，最多三次，退避为 5 秒、30 秒和 2 分钟。配置缺失、认证失败和协议错误不重试。人工“重新分析”永远创建新的 DiagnosisRun，不覆盖旧运行、快照或报告。

## 报告校验与展示

Dify 只能返回版本化 JSON 草案，字段为：已确认事实、待验证假设、引用、未知项和建议人工下一步。

- 已确认事实必须逐条引用快照中的 EvidenceItem，且只能描述可由证据直接支撑的现象；
- 待验证假设必须显式标记“待验证”，至少引用一条证据或已审批知识；
- 每个引用必须匹配本次运行中冻结的 ID 与内容指纹，或匹配本次工具回执；
- 建议只能面向人工，不得包含命令、脚本、URL 调用、配置变更或自动修复动作；
- 输出、数组、单段文字和原始草案摘要均有硬性大小上限。

前端只展示运行状态、可信报告、待验证假设、证据/知识引用和人工下一步。绝不展示模型思维链、系统提示词、能力凭证或工具内部参数。

## 故障安全与验收

- Dify 或知识库故障不得影响告警接收、Incident 生命周期、监控取证、飞书通知或人工处置；
- 所有外部调用设置固定允许地址、TLS、90 秒总超时和 64 KB 响应上限；
- 任何跨 Incident、跨环境、跨服务、任意监控查询、任意 URL 或写操作请求一律拒绝并审计；
- 平台应能解释一次调用为何允许、拒绝、重试、失败或进入人工复核；
- 每一份可信报告必须可回链至固定快照和具体证据/知识版本。

## 非目标

- Dify 直接连接任何数据库、监控系统、Kubernetes 或飞书；
- Dify 管理 Incident 状态、发送通知、执行命令或自动修复；
- 自动触发诊断；
- 将故障注入、实验标识或标准答案带入诊断输入；
- 展示或保留模型内部思维过程。
