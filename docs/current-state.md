# 当前状态

## 2026-08-31 Alert 生命周期与手动 Incident 规则

当前可用：

- Alertmanager 和 CloudEvents 接入；
- 告警源管理、可信环境、凭据生命周期和接收回执；
- 不可变 SignalEvent、来源事件精确重放和内容冲突保护；
- 一轮告警一条 Alert：firing 创建或更新，resolved 更新同一行；
- 恢复后新的开始时间创建新 Alert；
- resolved 先到和 firing 晚到可安全收敛，不把已恢复告警重新打开；
- Alertmanager 告警名称精确使用 `labels.alertname`，摘要和描述独立保存；
- 告警中心读取 Alert，展示“告警中/已恢复”、触发、首次接收、最近更新、恢复和持续时间；
- 趋势按 Alert 的 `first_received_at` 和接入源统计，resolved 不增加数量；
- 历史 SignalEvent 可通过有界、可重复的回填命令重建 Alert；
- Watchdog 心跳接收后安全忽略，不创建 SignalEvent 或 Alert。
- Incident 规则真实空列表和四步创建向导，不生成演示规则；
- 环境、来源、服务、聚合方式、1–60 分钟窗口和四种结构化 AND 条件；
- 草稿保存与编辑、复制、发布、停用、删除草稿、乐观并发和幂等操作；
- 最近 1、6、12、24 或 48 小时真实 Alert 的有界只读试运行；
- 当前版本成功且未截断的试运行作为发布门禁；发布本身不创建 Incident。

## 2026-09-01 Incident 实时评估基础

当前可用：

- 每次非重放的 Alert 新建或版本变化，会在同一事务写入持久化 Incident 评估任务；
- 后台 Worker 只读取 `PUBLISHED` 规则，并复用历史试运行的同一套规则语义；
- 命中规则后直接创建正式 Incident，或向同一规则、环境和分组边界下的未解决 Incident 追加 Alert；
- MySQL 唯一边界与事务重试共同保证并发任务收敛到一个未解决 Incident；
- Incident 编号由 MySQL 日序列表生成，格式为 `INC-YYYYMMDD-NNN`；
- Incident 严重级别只自动升级；全部关联 Alert 恢复时记录一次恢复活动，但不自动解决 Incident；
- Incident 创建和重要活动会在同一事务写入幂等通知 Outbox；
- 评估任务使用持久化租约、指数退避和最大尝试次数，应用启动后自动运行并在关闭时等待当前批次结束。
- Incident 列表默认展示 OPEN 和 ACKNOWLEDGED，支持状态、环境、严重级别和关键词筛选；
- Incident 详情展示来源规则、最多 500 条关联 Alert、最多 1,000 条不可变活动及飞书配置、线程和最近通知状态；
- Incident 支持人工确认和解决；写操作要求 Bearer Token、期望版本和幂等键，解决必须填写说明；
- 人工操作使用独立持久化幂等记录；重复请求不会重复改变状态、写时间线或产生通知。
- 可按环境创建、查看和修改飞书事故群路由，同一环境最多启用一个群；
- 飞书路由写操作支持持久化幂等和乐观版本控制；启用前会检查应用凭据是否完整；
- API 只返回凭据是否齐全及缺失的环境变量名，不返回 App ID、Secret、Token 或 Encrypt Key 的值。
- 飞书通知 Worker 会按 Incident 环境匹配启用群路由；创建时发送根卡片并绑定消息线程，后续 Alert 追加只更新根卡片；
- 确认、解决、严重级别升级和全部关联 Alert 恢复会更新根卡片并追加一条简短线程消息；
- 未配置环境路由时通知安全跳过；飞书临时故障采用持久化租约和有界退避，永久失败或重试耗尽只写一条 `NOTIFICATION_FAILED` 活动；
- 飞书租户 Token 只在进程内缓存并提前刷新；网络错误、限流和服务端错误可重试，鉴权、权限和参数错误直接停止重试。
- 飞书事件与卡片动作使用独立回调入口，校验时间、nonce、原始请求签名和 Verification Token，并支持 Encrypt Key 的 AES-CBC 加密回调；
- 只有已绑定 Incident 线程中的群聊文本、明确包含机器人 mention 且发送者不是机器人时，才会追加一条飞书沟通活动；重复事件、未知群、非线程消息和无关消息安全忽略；
- 卡片确认和解决复用平台 Incident 状态机与持久化幂等键；解决动作必须提供说明；飞书沟通只记录最长 4,000 字规范化纯文本和安全标识，不保存完整回调原文。
- Incident 前端数据层已接入真实列表、详情、确认、解决和飞书通知路由接口；状态、严重级别、活动类型与飞书协同状态使用中文安全投影；版本冲突会刷新真实详情并保留用户填写的解决说明。
- 主导航已提供 Incident 中心；默认展示未解决 Incident 的紧凑列表，详情按“当前情况、关联告警、处置与飞书”三栏组织，并支持确认、填写说明后解决和飞书事故群路由配置；页面不生成演示数据，低于 1,180px 自动切换单列分区。
- Incident 操作成功后会重新读取完整详情，规则依据、关联告警中文状态和处置时间线不会因局部响应而丢失；进入已解决状态时自动关闭解决表单。
- `/health` 提供 Incident 评估任务、通知任务和飞书配置的有界健康摘要；只返回待处理/租约中/失败数量、最早待处理时间、最近成功时间和最近错误码，不返回任务 ID、payload、堆栈、Chat ID 或凭据。
- 数据库升级会幂等恢复缺失的系统 Alertmanager、CloudEvents 和人工来源，不覆盖用户创建的接入源。

尚未可用：

- 飞书真实投递契约已实现并通过可注入传输层测试，但尚未使用真实飞书测试应用和测试群完成沙箱联调。

已经从运行时和用户界面移除：

- 告警分组、批次、聚类、风暴收敛和人工分组；
- 旧服务目录、旧关联任务和旧事故运营模型；
- 事故运营、DiagnosisRun、自动取证和 AI 分析；
- 人工事故报告入口及相关后台 Runner。

## 当前告警读取契约

- 列表按 Alert 首次接收时间倒序；
- 支持来源、生命周期状态、级别、环境、服务、首次观测时间、首次接收时间和文本筛选；
- 每行展示一个告警周期，不把 firing 和 resolved 展示为两条业务告警；
- 点击当前行后集中展示环境、服务、资源、生命周期时间、持续时长、接入源和描述；
- 页面不展示完整 SignalEvent 原始字段，不返回批次、事故、根因、处理过程或 AI 字段。

## 当前趋势契约

- 默认最近 1 小时，支持最近 5 分钟至最近 2 天的九种快捷范围；
- 支持最长 48 小时的自定义时间，并可直接在图表中拖选窗口；
- 每个接入源独立成线，无告警时间桶补零；
- 统计口径固定为 Alert 首次接收时间；恢复通知不增加折线计数；
- 拖选区域按完整时间桶对齐，选区、时间文字和下方告警列表使用同一窗口；
- 趋势不可用不阻断告警列表和详情。

## 当前 Incident 规则契约

- 平台不内置规则，也不展示虚构样例；
- 环境必选且规则不会跨环境，来源与服务可留空；
- 分组只允许同一服务或同一实体；
- 条件类型为不同 Alertname 数量、活动告警数量、不同实体数量和最高告警级别，单类条件不可重复且全部使用 AND；
- 试运行最多扫描 10,000 条 Alert，最多返回 100 个命中结果和每组 10 个示例 Alert；
- 修改规则会使旧试运行失效；发布版本不可直接修改，只能复制为新草稿或停用；
- 规则管理不可写入 Incident、SignalEvent 或 Alert。

## 已知边界

- 旧 Alembic 历史迁移和历史复杂业务表仍保留，但运行时不访问；
- 正式 Incident 已可由发布规则异步生成、去重，并通过前端列表、详情或 API 完成人工确认和解决；
- 当前 Alert 只有业务生命周期状态，没有确认、抑制、关闭等人工处置状态；
- 本地既有 SignalEvent 需要在数据库升级后执行一次回填，才会出现在新的告警中心。

## 2026-09-02 Incident 监控取证实施中

当前已实现的后端基础能力：

- EvidenceRun、EvidenceItem、两小时取证窗口、部分成功状态和持久化租约模型；
- Prometheus、Elasticsearch、SkyWalking 监控数据源管理 API；凭据只保存环境变量引用；
- `common-service`、HTTP、JVM、MySQL 四类版本化预定义取证包；
- Prometheus 有界指标采集、ELK 白名单日志采集与敏感信息清理、SkyWalking GraphQL 变量化链路采集；
- Trace ID 与日志的确定性跨源关联，且禁止输出根因、置信度或自动修复结论；
- MySQL 迁移、唯一启用来源、唯一自动运行、唯一证据键和任务租约边界。

- Incident 创建事务尚未自动写入 EvidenceRun 与取证任务；
- 取证 Worker、人工重新取证 API、健康摘要和 Incident 第三版取证页面尚未实现；
- 三个测试环境监控系统尚未完成真实只读联调，因此当前不能宣称 Incident 会自动产生监控证据。
