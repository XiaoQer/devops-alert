# 产品定义

## 当前目标

建设一个可靠、简单的告警接入、Incident 识别、监控取证与人工处置基线。当前版本管理告警接入源，保留可信 Alert 生命周期，允许用户用真实历史 Alert 验证并发布 Incident 规则，再由后台异步创建正式 Incident、执行版本化只读监控取证，并通过页面或 API 完成人工处置。

## 当前用户流程

1. 操作员在“接入源管理”创建 Alertmanager 或 CloudEvents 来源；
2. 平台生成只显示一次的接入 Token；
3. 外部系统通过来源专属 Webhook 发送告警；
4. 平台完成认证、容量校验、字段规范化和传输幂等，并忽略 Alertmanager 的 Watchdog 心跳；
5. 每次首次收到的非心跳通知保存为不可变 SignalEvent；
6. 平台在同一事务中把 SignalEvent 投影到 Alert：firing 新建或更新，resolved 更新同一轮 Alert；
7. 操作员在“告警中心”查看一轮告警从触发到恢复的状态、时间和描述。
8. 操作员在“Incident 规则”中创建草稿，明确环境、聚合方式、窗口和结构化条件；
9. 平台只读扫描真实历史 Alert，返回命中结果；成功且未截断的当前版本才允许发布。
10. 发布规则命中新 Alert 后，后台异步创建或更新正式 Incident；
11. 操作员查看 Incident 详情并确认或解决；
12. 操作员可按环境配置固定飞书事故群，凭据不完整时不能启用路由。
13. 新 Incident 自动执行 Prometheus、ELK 和 SkyWalking 预定义只读取证；操作员可查看历史证据或幂等触发重新取证。

## 当前可用功能

- 接入源创建、编辑、启停、环境配置、Token 轮换与撤销；
- Alertmanager 和 CloudEvents Webhook；
- 接收验证、精确重放、冲突保护、回执与有界审计；
- 独立 Alert 生命周期投影，状态为“告警中”或“已恢复”；
- 告警分页、筛选，以及列表内紧凑展开生命周期详情；
- 按接入源和 Alert 首次接收时间查看新告警趋势，支持九种快捷时间、自定义时间和图表拖选；
- 历史 SignalEvent 可重复回填为 Alert。
- 手动 Incident 规则的草稿、编辑、复制、发布、停用和有界审计；
- 最近 1、6、12、24 或 48 小时真实 Alert 的只读试运行；
- 后端生成的中文规则说明、乐观并发和发布前试运行门禁。
- Incident 异步创建、同边界收敛、列表、详情、确认和解决；
- 按环境配置飞书事故群路由及凭据完整性自检；
- 飞书根卡片发送与状态更新、Incident 线程沟通回流和卡片确认/解决动作。
- 按环境管理 Prometheus、Elasticsearch 和 SkyWalking 监控源，Secret 只引用运行环境变量；
- 独立监控数据源页面支持创建、编辑、启停和真实只读连接检测，并展示最近状态、耗时、版本与失败原因；
- 新 Incident 唯一自动取证、部分成功、缺失来源安全退化、历史运行和人工重新取证；
- Incident 详情中的中文取证结果、来源状态、时间范围和取证包摘要。

## 当前明确不做

- 候选 Incident 和人工批准步骤；
- 告警批次、聚类、风暴收敛和文本相似度；
- 服务拓扑；
- DiagnosisRun 和 AI 分析；
- 自动修复。
- 真实飞书测试应用和测试群的沙箱联调尚未完成。

这些能力以后必须重新完成产品设计并由用户确认，不能从旧实现恢复。

## 产品原则

- SignalEvent 忠实保存接收事实；Alert 表示一次告警生命周期，两者不能混用；
- 同一来源、同一来源告警键、同一开始时间只形成一条 Alert；
- resolved 只更新 Alert 状态，不增加告警总数和趋势数量；
- 告警名称使用 `alert_name`，Alertmanager 精确取自 `labels.alertname`；摘要和描述不充当名称；
- 趋势统计只使用 Alert 的平台首次接收时间；
- `alertname=Watchdog` 是监控链路心跳，不作为业务告警保存或展示；
- service 等可选标签缺失时仍正常接收，不为补充字段读取 Kubernetes；
- 原始请求全文和 Secret 不进入列表、日志或 API 响应。
- 平台不内置 Incident 规则；所有规则由用户创建并先以真实历史 Alert 试运行；
- 发布规则本身不创建 Incident；发布后由新到达或发生版本变化的 Alert 异步触发正式 Incident 评估。
